# การส่งข้อมูลเข้าระบบบัญชี BPlus

เอกสารนี้สำหรับฝ่ายบัญชี — อธิบายว่าไฟล์ที่ ChunERP ส่งออกแต่ละไฟล์คือรายการบัญชีอะไร
ลงบัญชีอย่างไร และตัวเลขกระทบยอดกันอย่างไร

---

## 1. เกิดอะไรขึ้นบ้างในหนึ่งรอบการเลี้ยง

| ลำดับ | เหตุการณ์จริง | เอกสาร | ไฟล์ที่ส่งออก |
|---|---|---|---|
| 1 | เจ้าหน้าที่ส่งไข่ไหม/วัสดุให้เกษตรกรเป็นเครดิต | ใบจอง + บันทึกส่งของ | `BPLUS_AR_*.csv` |
| 2 | เกษตรกรนำรังไหมสดมาขาย บริษัทรับวัตถุดิบเข้า | ใบรับซื้อรังไหมสด | `BPLUS_PURCHASE_*.csv` |
| 3 | หักหนี้ค่าไข่ไหมออกจากค่ารังไหม | ใบหักกลบ | `BPLUS_OFFSET_*.csv` |
| 4 | จ่ายส่วนต่างให้เกษตรกร | ใบสำคัญจ่าย | `BPLUS_PAYMENT_*.csv` |

**สำคัญ:** ไฟล์ซื้อ (ข้อ 2) ต้องเป็น **ยอดเต็ม** ตามใบรับซื้อ ไม่ใช่ยอดหลังหักหนี้
เพราะบริษัทได้รับวัตถุดิบมาเต็มจำนวนจริง ๆ ส่วนการหักหนี้เป็น *วิธีชำระ* ไม่ใช่ส่วนลด

## 3. ทำไม Dr = Cr

**แต่ละใบเดบิตเท่ากับเครดิตอยู่แล้ว** ส่วนการลบ `28,297.28 − 1,570 = 26,727.28`
ไม่ได้เกิดในใบใดใบหนึ่ง แต่เกิด **ในบัญชีเจ้าหนี้** — เจ้าหนี้เป็นบัญชีพักที่ปิดตัวเองเมื่อจบรอบ

### บัญชีแยกประเภท: เจ้าหนี้ - เกษตรกร (สมชาย)

| รายการ | เดบิต | เครดิต | คงเหลือ |
|---|---:|---:|---:|
| ซื้อรังไหมสด (ใบ 2) | | 28,297.28 | 28,297.28 |
| หักกลบลบหนี้ (ใบ 3) | 1,570.00 | | 26,727.28 |
| จ่ายเงิน (ใบ 4) | 26,727.28 | | **0.00** |

### บัญชีแยกประเภท: ลูกหนี้การค้า - เกษตรกร (สมชาย)

| รายการ | เดบิต | เครดิต | คงเหลือ |
|---|---:|---:|---:|
| ตั้งหนี้ค่าไข่ไหม (ใบ 1) | 1,570.00 | | 1,570.00 |
| หักกลบลบหนี้ (ใบ 3) | | 1,570.00 | **0.00** |

### สรุปผลรวมทั้งรอบ

| บัญชี | ผลกระทบสุทธิ | ความหมาย |
|---|---:|---|
| เงินสด / ธนาคาร | −26,727.28 | เงินที่จ่ายออกจริง |
| วัตถุดิบ - รังไหมสด | +28,297.28 | รังไหมที่รับเข้าโรงงาน |
| รายได้ขายวัสดุการเลี้ยง | +1,570.00 | ขายไข่ไหม/วัสดุให้เกษตรกร |
| ลูกหนี้ / เจ้าหนี้ - เกษตรกร | 0.00 | ปิดยอดหมดเมื่อจบรอบ |

ตรวจสอบ: `28,297.28 = 26,727.28 + 1,570.00` — วัตถุดิบที่ได้มา = เงินที่จ่าย + หนี้ที่หักกลบ
เดบิตรวม 57,164.56 เท่ากับเครดิตรวม 57,164.56

**ข้อผิดพลาดที่ต้องเลี่ยง:** ถ้าลงซื้อวัตถุดิบเป็นยอดสุทธิ 26,727.28 ต้นทุนวัตถุดิบจะขาดไป
1,570 บาท และลูกหนี้ 1,570 จะค้างในระบบตลอดไปเพราะไม่มีอะไรมาหักกลบ

## 4. รายการสินค้าในไฟล์ซื้อ

ไฟล์ `BPLUS_PURCHASE` มีหนึ่งบรรทัดต่อหนึ่งชั้นคุณภาพที่มีน้ำหนักจริง (ชั้นที่ไม่มีน้ำหนักจะไม่ส่ง)

| ItemCode | ชั้นคุณภาพ | หน่วย | บิลเป็น |
|---|---|---|---|
| `COCOON-GOOD` | รังสดรับซื้อ-ดี | กิโลกรัม | น้ำหนักรัง |
| `COCOON-DAMAGED` | รังสดรับซื้อ-เสีย | กิโลกรัม | น้ำหนักรัง |
| `COCOON-DOUBLE` | รังสดรับซื้อ-เสียแฝด | กิโลกรัม | น้ำหนักรัง |
| `COCOON-THIN` | รังสดรับซื้อ-เสีย บาง (0) | กิโลกรัม | น้ำหนักเศษ |
| `COCOON-FLOSS` | ปุยไหม-ตกเกรด (5) | กิโลกรัม | น้ำหนักเศษ |

แยกรายการเพราะแต่ละชั้นเข้าสู่การผลิตคนละทางและราคาต่างกัน ต้นทุนผ้าไหมที่ผลิตออกมา
คิดจากน้ำหนักรายชั้นนี้ — ถ้าส่งเป็นยอดรวมก้อนเดียว บัญชีจะรู้แค่ว่าจ่ายเงินไปเท่าไร
แต่ไม่รู้ว่าได้วัตถุดิบอะไรเข้ามาเท่าไร

**ต้องยืนยันกับฝ่ายบัญชี:** รหัสสินค้าชุดนี้ ChunERP ตั้งเอง หากใน BPlus มีรหัสสินค้าอยู่แล้ว
แจ้งรหัสจริงมาได้ แก้ที่ [`src/services/accounting/bplus.ts`](../src/services/accounting/bplus.ts) ที่เดียว

## 5. รูปแบบไฟล์

- CSV คั่นด้วยเครื่องหมายจุลภาค เข้ารหัส **UTF-8 พร้อม BOM** (ถ้าไม่มี BOM Excel ภาษาไทยจะอ่านชื่อเป็นตัวยึกยือ)
- วันที่รูปแบบ `YYYY-MM-DD` **ค.ศ.**
- จำนวนเงินทศนิยม 2 ตำแหน่ง ไม่มีเครื่องหมายคั่นหลักพัน
- `CustCode` / `VendCode` = รหัสเกษตรกร · `BatchNo` = รอบการเลี้ยง ใช้กระทบยอดข้ามเอกสาร

## 6. การกันส่งซ้ำ

ทุกแถวที่ส่งออกแล้วจะถูกประทับเลขที่ชุด (เช่น `BX-2569-0001`) และหายจากรายการค้างส่ง
ส่งซ้ำจะถูกปฏิเสธ เพราะการนำเข้าซ้ำหมายถึงยอดลูกหนี้/เจ้าหนี้ของเกษตรกรเพิ่มเป็นสองเท่า
ประวัติการส่งออกทั้งหมดดูได้ที่หน้า **ส่งข้อมูลบัญชี BPlus**

## 7. สิ่งที่ยังต้องยืนยันกับฝ่ายบัญชี

1. ชื่อคอลัมน์ในเทมเพลตนำเข้าจริงของ BPlus (ชุดปัจจุบันตั้งจากข้อมูลขั้นต่ำที่ระบบ AR/AP ต้องใช้)
2. รหัสผังบัญชีของ ลูกหนี้ / เจ้าหนี้ / วัตถุดิบ-รังไหมสด / รายได้ขายวัสดุการเลี้ยง
3. รหัสสินค้าของรังไหมแต่ละชั้นคุณภาพ
4. รูปแบบวันที่ที่ BPlus รับ (ค.ศ. หรือ พ.ศ.)
5. รหัสสาขา/จุดรับซื้อที่ใช้ใน BPlus

ทั้งหมดนี้แก้ที่ไฟล์เดียวคือ [`src/services/accounting/bplus.ts`](../src/services/accounting/bplus.ts)
